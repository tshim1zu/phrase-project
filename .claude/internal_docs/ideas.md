LLM連携やUI、さらに形態素解析も排除して、**「統計的アプローチのみでエンジン（抽出ロジック）を極限まで強化する」**という方針、非常に硬派で素晴らしいです。

現在の `japhrase` は N-gram の単純生成とヒューリスティックなスコア計算に基づいていますが、これを「バチクソ強化」するための、**辞書いらず・教師なし・統計ガチ勢**向けのアプローチを提案します。

これらは現在の `extracter.py` のロジックを根本から書き換えるレベルの強化案です。

### 1. 「隣接種類数」と「分岐エントロピー」の導入 (精度強化)

現在のロジックの最大の弱点は、「どこが単語の切れ目か」を頻度と長さだけで判定している点です。これを統計的に解決する最強の手法がこれです。

* **理論**: 「ある文字列の次にくる文字の種類が急激に増える場所が、単語の境界である」という考え方です。
* 例: 「機械学」の後には「習」しかほぼ来ない（エントロピーが低い＝単語の途中）。
* 例: 「機械学習」の後には「は」「を」「の」「モ（デル）」など多様な文字が来る（エントロピーが高い＝単語の境界）。


* **実装案**:
* **Accessory Variety (AV)**: 左隣接種類数（左にどんな文字が来るか）と右隣接種類数（右にどんな文字が来るか）をカウントします。
* **Branching Entropy (BE)**: 単なる種類数ではなく、その確率分布のエントロピーを計算します。
* **新スコア**: `CurrentScore * min(LeftBE, RightBE)` のように、境界の確らしさを重み付けします。これにより、「意味の通った塊」だけを強烈にフィルタリングできます。



### 2. Suffix Array (接尾辞配列) + LCP配列への移行 (速度・メモリ強化)

現在の `make_ngrampieces` は、テキストから全てのN-gramをリストに展開しており、長文になるとメモリが爆発します。これをアルゴリズムレベルで解決します。

* **理論**: テキストの全接尾辞を辞書順にソートした配列（Suffix Array）を作ると、出現箇所や頻度の計算が高速に行えます。
* **実装案**:
* Pythonの `pydivsufsort` などのライブラリを使うか、自前で `SA-IS` アルゴリズム等を実装します。
* **LCP (Longest Common Prefix) 配列** を併用することで、「重複している部分文字列（＝フレーズ候補）」をリスト生成なしに  で洗い出せます。
* これにより、GB単位のテキストでも高速に処理可能になり、N-gram長の制限（現在は `max_length` 依存）を撤廃できます。



### 3. スコアリング関数の統計的刷新 (順位付け強化)

現在のスコア `freq * log(1+freq) + len * log(len)` は経験則的ですが、これを統計的に有意な指標に変えます。

* **PMI (自己相互情報量)**:
* 「A」と「B」が別々に現れる確率よりも、「AB」として連続して現れる確率がどれだけ高いかを見ます。
* これにより、「頻度は高いがただの組み合わせ（例: "ていう"）」を下げ、「頻度はそこそこだが結びつきが強い専門用語（例: "ニューラルネットワーク"）」を上位に上げられます。


* **C-value の非形態素解析版**:
* `THEORY.md` にある C-value は通常、形態素解析前提ですが、これを文字単位N-gramに応用します。
* 「より長いフレーズの一部として出現している回数」を差し引くことで、「機械学習」が抽出されたときに「学習」という部分文字列のスコアを下げる処理を、より数学的に厳密に行えます。



### 4. Rust / Cython によるコアの書き換え (物理的強化)

「エンジンのみを強化」なら、Pythonのループ処理自体の限界を突破します。

* **案**: 上記の Suffix Array 構築やエントロピー計算部分のみを **Rust** で書き、`PyO3` で Python モジュールとしてバインディングします。
* **効果**: 文字列操作における Python のオーバーヘッドを消し去り、処理速度を10倍〜100倍オーダーで高速化できます。「バチクソ強化」には最も即効性があります。

### まとめ：最強の「エンジン」構成案

これらを組み合わせた新しい `Japhrase Core 2.0` は以下のようになります。

1. **データ構造**: Suffix Array + LCP Array (Rust実装)
2. **抽出ロジック**: LCP配列を走査し、頻出部分文字列を列挙 (メモリ消費最小)
3. **境界判定**: 分岐エントロピー (Branching Entropy) で単語境界を統計的に推定
4. **スコアリング**: 頻度 × エントロピー × PMI でランク付け

これなら外部ライブラリも辞書も一切使わず、純粋な統計とアルゴリズムの力だけで、現行版とは次元の違う抽出精度と速度が出せます。
